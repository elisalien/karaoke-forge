# Révision du 24 octobre 2026 — Karaoke Forge (branche `refonte-fusion`)

Grosse révision de maintenance : annulation fiable, timeline au niveau d'un éditeur de sous-titres,
interface redessinée et épurée, raccourcis par espace, robustesse, et surtout **une application de
bureau autonome** (installeur + exécutable portable). Rien n'a été poussé sur GitHub.

---

## En bref

- **Ctrl+Z réparé en profondeur** : 14 défauts corrigés (voir plus bas). Deux piles séparées, une pour les timings et paroles (Préparer), une pour les réglages (Style). Boutons ↶ ↷ dans l'en-tête.
- **Timeline** : 12 bugs corrigés, aimant sur les attaques de l'audio, infobulle en direct pendant un glissé, Échap qui annule le geste, forme d'onde plus jamais recalculée pendant qu'on glisse.
- **Interface « studio sombre »** : anthracite, un seul accent cyan, typo système lisible, casse de phrase partout, pictos cohérents, un seul style de bouton. Les doublons ont disparu, l'étape 4 ne montre que la ligne sélectionnée, les réglages sans objet se cachent.
- **Live verrouillé** : plus d'Enregistrer / Fichier / Exporter / Ctrl+Z pendant le show.
- **Application de bureau** (`desktop/`) : fenêtre native Electron, companion embarqué, `Karaoke-Forge-Setup-1.0.0.exe` et `Karaoke-Forge-1.0.0-portable.exe` dans `desktop/dist/`.
- **Autotest** : 39 vérifications rejouées dans la vraie application, fenêtre cachée (`node tools/smoke.mjs`).

## Ce qui a été corrigé dans l'annulation

| Avant | Maintenant |
|---|---|
| La sélection disparaissait à chaque Ctrl+Z : impossible de re-décaler | La sélection revient telle qu'elle était |
| Le message « Annulé : X » nommait la mauvaise opération | Libellés exacts, dans les deux sens |
| Flèches tenues = un niveau d'annulation par répétition, l'historique sautait | Une rafale = une étape |
| Le calage entier = une seule étape, Ctrl+Z en plein calage cassait l'index | Ctrl+Z en calage recule d'une syllabe ; après coup, une rafale de frappes = une étape |
| La zone de texte des paroles n'était pas restaurée | Texte, titre et artiste suivent ; la frappe elle-même est annulable |
| Après Ctrl+S puis Ctrl+Z, l'app affichait « enregistré » | Le document repasse « non enregistré », l'autosave repart |
| Rétablir pouvait écraser des frappes non enregistrées | Rétablir vérifie d'abord l'état vivant |
| Entrer/sortir du calage sans frapper marquait « modifié » et perdait le « rétablir » | Seul un vrai changement compte |
| En Style, Ctrl+Z défaisait silencieusement un timing | Pile séparée pour le style ; en Préparer, le style n'est jamais touché |
| En Live, Ctrl+Z était muet | Message clair : rien n'est annulable pendant le show |
| Ctrl+Z pendant un glissé pouvait planter | Le glissé est d'abord annulé proprement |
| La sauvegarde automatique pouvait être écrasée au démarrage par un document vide | Corrigé (`Doc.clean` annule le minuteur) |
| Le calage n'alimentait pas l'autosave | Chaque frappe le fait |
| Aucun bouton visible | ↶ ↷ dans l'en-tête, infobulle = prochaine action annulable |

## Ce qui a changé dans la timeline

- `Échap` (ou la perte de la fenêtre) annule le glissé en cours ; rien ne bouge.
- Infobulle en direct : temps de début/fin, écart en ms, nombre de syllabes déplacées.
- Lasso borné dans le temps : le défilement automatique ne le déforme plus ; `Alt` retire de la sélection.
- Collisions contre la **fin réelle** des voisines ; une ligne ne chevauche plus la précédente ; le clavier (`Maj+flèches`, `I`, `O`) respecte les mêmes bornes.
- « Décaler la suite » : l'aimant n'accroche plus les syllabes qui bougent avec le bloc.
- Double-clic sur la règle : tout voir **sans** déplacer la tête.
- La boucle suit la ligne qu'on déplace.
- Deux calques en cache (vue / blocs) : un glissé ne recalcule plus la forme d'onde.
- **Suivre** se met en pause quand on défile pendant la lecture, et reprend au prochain déplacement de la tête.
- Attaques détectées dessinées sous la règle, calculées en tâche de fond au chargement, et cibles d'aimant.
- Survol : bloc surligné, temps sous le curseur dans la règle, zoom et état de l'aimant affichés à droite.
- Poignées saisissables sur les blocs étroits ; `+` `−` zooment autour de la tête ; `Ctrl+A` deux fois = tout ; Boucle et Sur l'attaque dans la barre de la timeline.

## Interface

- Thème « studio sombre » : `--bg #15171a`, accent `#3fb8d8`, ambre pour « non enregistré », rouge pour supprimer. Zéro halo, zéro trame CRT, une seule ombre (menus). Typo Segoe UI ; mono réservé aux temps, compteurs et touches.
- Casse de phrase partout (boutons, titres, menus, dialogues). Libellés complets (« Couleur du contour » au lieu de « Coul. contour »…).
- Un jeu de 17 pictos SVG remplace les glyphes Unicode disparates ; `aria-label` sur tous les boutons symboles ; cases à cocher accessibles au clavier ; `prefers-reduced-motion` respecté.
- Préparer : étape 4 filtrée sur la ligne sélectionnée (*Toutes les lignes* pour tout voir) ; un seul libellé « Effacer le calage de la phrase » ; import .ass/.lrc seulement dans Fichier ; étape 5 réduite à un bouton.
- Style : réglages dépendants masqués (`when` dans le schéma) ; un seul bloc Tempo ; mode Simple/Expert et onglet mémorisés ; l'ambiance se désélectionne dès qu'un réglage change ; compteur de particules seulement en Expert.
- Live : en-tête vidé, recalage ±0,1 s non enregistré dans le morceau, « Supprimer » en toutes lettres pour la bibliothèque, table de raccourcis remplacée par F1.
- Raccourcis : Style ne touche plus aux timings (`Suppr`, `I`, `O`, `M`, `C`…) ; l'aide F1 est générée depuis la table des raccourcis, par espace.

## Robustesse

- Erreurs imprévues (`error`, `unhandledrejection`) → un message, une fois, et la console.
- Export sans encodeur AAC → l'app prévient que la vidéo sera muette.
- Bibliothèque : échecs d'écriture du set et de suppression signalés ; `onblocked` géré.
- Companion absent : les tentatives Link s'espacent (2 s → 30 s).
- Décodage audio : indicateur dans l'en-tête ; analyse des attaques en tâche de fond, sans figer la fenêtre.

## L'application de bureau

```
desktop/
  main.js         fenêtre native, schéma kf://app/, écran scène en seconde fenêtre, companion embarqué, mode --selftest
  prepare.mjs     reconstruit karaoke-forge.html et le copie avec companion/ dans desktop/app/
  make-icon.mjs   génère build/icon.ico sans dépendance
  package.json    scripts : start · test · dist · dist:portable (Electron 45, electron-builder 26)
```

- `F12` ouvre les outils de développement, `F11` le plein écran ; aucun menu : tous les raccourcis vont à l'app.
- Le companion tourne dans un processus utilitaire ; yt-dlp et ffmpeg se déposent dans `%AppData%\Karaoke Forge\bin` (chemin affiché dans l'app).
- Les fenêtres mémorisent leur position. Une seule instance à la fois.
- Non signé : SmartScreen demande confirmation au premier lancement.

Construire : `cd desktop && npm install && npm run dist` → `desktop/dist/Karaoke-Forge-Setup-1.0.0.exe` et `Karaoke-Forge-1.0.0-portable.exe`.

## Comment tester

**Automatiquement** — depuis `karaoke-forge/` :

```
node tools/smoke.mjs
```

Reconstruit l'app, la lance dans Electron (fenêtre cachée), rejoue : décodage WAV, découpage, 21 frappes, annulation/rétablissement, 30 décalages = 1 étape, bornes, libellés, glissé + Échap, pile Style, Live neutre, enregistrement, autosave, saisie des paroles, companion joignable. Échoue sur toute erreur console.

**À la main** — lance `desktop/dist/Karaoke-Forge-1.0.0-portable.exe` :

1. Glisse un mp3. Colle trois lignes, **Découper en syllabes**, **Caler en écoutant**, `F` sur chaque syllabe.
2. Dans la timeline, glisse une syllabe : l'infobulle suit ; `Échap` en cours de route la remet en place.
3. Sélectionne une syllabe, tiens `Maj+→` deux secondes, puis `Ctrl+Z` une fois : tout revient, la syllabe reste sélectionnée.
4. Onglet **2 Style** : change une ambiance, `Ctrl+Z` : l'ambiance précédente revient, les timings n'ont pas bougé.
5. `Ctrl+S`, puis **3 Live** : l'en-tête ne montre plus qu'Aide ; `Ctrl+S` affiche un message et ne fait rien.
6. **Ouvrir l'écran scène** : une seconde fenêtre native s'ouvre, `F` la met en plein écran.
